# UC6101B 実機検証

更新日: 2026-09-14。従来版の21.x検証と、23.0ドック更新への追従版の確認範囲を分けて記載します。

## 23.0ドックアップデート追従版：2026-09-14

純正ドックのコマンド`0x02`への応答値が`0003005F→0003006E`に変化したことをPD通信で確認し、
MOKINも同じ値を返すよう変更しました。下表はSwitch 2システムバージョン23.0でのユーザー報告です。

| 確認項目 | 結果 |
|---|---|
| `0003006E`版の書き込み後の起動 | 成功 |
| Switch 2の外部ディスプレイVRR設定 | 有効化できた |
| 可変リフレッシュ出力の実動作 | **未確認** |
| 変更後のコマンド`0x02`のPD応答再採取 | 未実施 |
| 今回の生成物での2画面出力・充電契約・スリープ復帰の再検証 | 未実施。下記21.xの結果は従来版の記録 |

**VRR対応を確認したものではありません。** VRR設定を有効化できても、実際に可変リフレッシュで
出力できるとは限りません。変更前の応答値でも同じ設定を有効化できたかは未確認で、設定の可否が
今回の変更によるものかも確定していません。

参考として、L32p-30をPCからMOKIN経由のUSB-Cで接続した構成では、AMD SoftwareがFreeSyncを
非対応と表示しました。これはSwitch 2でのVRR実動作を直接検証した結果ではなく、すべての接続先
でVRRが使えないことを示すものでもありません。

パルスも含む従来版では、完全電源断後にTVモード移行と上記VDM応答の両方を確認しています。

## 生成物の静的検証

ビルダーの生成結果は、2026-09-14に別途作成して起動確認した`0003006E`版のHEXとファイル全体で
一致します。従来版からの実データ差分は`0x4C9F: 5F→6E`と`0xFFFF: 51→35`のみです。
Intel HEXレコードchecksum、変更前バイト、変更アドレス集合、Block 1 CRC、image checksum、
出力SHAの検査を維持しています。

## 未確認

- VRRの実動作、および応答値の変更とVRR設定の可否との因果関係
- ドック上のすべてのUSB周辺機器
- Switch 2以外のすべてのDP Alt Modeホスト
- 別ロット、別ファームウェア版のUC6101B

実機1台での結果であり、未確認範囲を保証するものではありません。問題が起きた場合に戻せるよう、
書き込み前に公式イメージを保管してください。
